# 六个正确样本的轨迹抽查

本报告只读检查本次已完成实验的 6 个正确样本，共 102 轮、123 次工具调用。远程冻结运行目录为 `<部署根目录>`。证据来自 `runs/hosted_qwen38_first10/<variant>/_traces/qid_<qid>/single.json` 的模型可见正文、全部工具参数和返回，以及对应 `api_transport.jsonl` 的数值记录。未读取或摘录隐藏推理正文，未复制原始完整轨迹，未修改远程文件。轮号沿用轨迹的零起始编号。

## search_paging / q122：Juan Gabriel，2016

**结论：有直接证据，搜索策略明显拖长。** T22 才首次调用 rerank，此前大量近义日期查询、猜测演出场馆及美国人口方向。全程 12 次 search、36 个子查询，最后导入池为 12,711 个文档；没有翻页行为。

- T22 的 rerank 第 4 项将 Juan Gabriel 无录音争议段从 BM25 第 14 提到第 4；另一个相关段原本就是第 6，重排后仍第 6。因此可确认正文定位有效，不能把效果全部归为排序提升。
- T23 才出现“找到关键线索”的可见进展，Bash 核对出生于 1950 年、1990 年 Palacio de Bellas Artes 演出和 2016 年去世，随后定向搜索 Parácuaro。T24 官方 `www.economia.gob.mx/paracuaro.txt` L71 给出 2020 年人口 26,832、较 2010 年增长 5.88%。最终答案不是无证据猜测。
- T5、T8、T13 等全池 grep 被超长行淹没；T13 截去 3,935,752 字符。`head` 限行但不限制行长，数字表达式也会匹配其他数字中的 `5.88`。这些主要是模型筛选策略问题；工具已在 T13 提示缩窄到 `rg -l/-o`。
- 建议在重复搜索只带回元数据或相同候选时，提前切换到正文检索；对数值使用边界和窄输出。A 的预览经常只有标题/目录，存在信息量不足的设计取舍，但本例没有检验翻页能力。

## search_paging / q153：Walter Allen

**结论：答案有两处档案支持；主要成本来自 Bash 环境契约不清与模型恢复。** 正确档案 `archiveswest.orbiscascade.org/xv52062.txt` 在 T0 已出现，T1–2 又搜索近似线索。

- T3 使用未提供过的 `/home/jordan/projects/workspace`，返回 `cd: ... No such file or directory`。工具结构化 `error` 为空，但文本有 `[exit=1]`，故不能只用 `error` 字段判断命令成功。
- T6 建立 `/tmp/a.txt`、`/tmp/b.txt`；T7 试图在下次 Bash 复用，T8–9 才发现文件消失。T10 又尝试在只读工作目录建文件失败。T11 将流水线放进同一次调用才恢复。每次 Bash 的 `/tmp` 不持久是应明确的工具契约，使用虚构工作目录与未及时适应则是模型策略问题。
- T12 rerank 首项就是妻子 Gertie Fae Perkins 的档案段，BM25 第 1→rerank 第 1；本次价值主要是正文及 read offset，而非提升名次。T13 read 到妻子及搬迁记录，T14 grep、T15 read 到 Frank Perkins 和 Walter Allen 在 1911–15 年合伙、1917–20 年只列 Frank，T16 回答 Walter Allen。
- 档案的两段分别写搬到 3rd Avenue 为约 1906 年、1916 年，最终未提醒这一时间差；不影响“谁不再列名”的直接结论。后续应区分源材料不一致与模型事实错误。

## auto_rerank / q127：Bruce Chapman

**结论：完整证据链成立，自动重排有效，但不能消除模型在错误方向上的耗时。** T0–17 多次猜奖项并巡查目录/全文，直到 T18 定向搜索 Hanushek 致谢才拿到关键段。

- T11 查询 Tencent 创办者奖项，自动重排返回 2016 年 Yidan Prize；T12 第 6 项返回 Hanushek 的官方短传；T13 核对空军服役。
- T18 三个子查询均自动返回含 Bruce Chapman 的完整致谢段，分别 BM25 第 4→第 1、第 2→第 1、第 1→第 1。T19 文章开头确认 2013 年、作者和标题；T20 有限上下文 grep、T23 Python 字符切片再次读取致谢，T24 最终回答。
- 一共有 32 次 Bash。T8–10、T16、T19 的输出截断；T19 `head -40` 遇超长 PDF 提取行截去 46,256 字符。若干 `.{N}` 固定长度前后文表达式返回空，即使相应词在文档中出现，也会因前后字符不足而漏掉。T20 已有完整致谢后仍多次查找精确短语“valuable comments”，但原文用的是“Helpful comments”。
- 改进应放在及时定向搜索、避免硬性字符长度匹配，以及拿到可核验证据后的停止规则。最慢 API 190.17 秒主要发生于首次工具调用之前，不能归给 rerank 或 GPU 队列。

## auto_rerank / q153：Walter Allen

**结论：这 6 例中最清晰的排序正面证据，3 轮闭环。**

- T0 第 3 个子查询 `photography studio partners listed city directory 1910 1920` 把 Allen/Perkins 关键段从 BM25 第 265 提到 rerank 第 8，完整显示两位合伙人、1916 年搬迁、1917–20 年只列 Frank，并提供精确 read 参数。
- T1 按该位置 read，再用 grep 定位 Gertie Fae Perkins 和后续搬迁；T2 得出 Walter Allen。与 A153 一样，档案存在约 1906/1916 的时间差，最终没有说明，但身份结论有直接支持。
- T0 仍给模型 3×10 个正文段（约 25,669 字符），且并行列目录没有明显必要。search 运行 66.18 秒，含三个子查询的自动重排及准备成本；不能拿它与表中单次 API 时间混为一谈。

## no_bash / q127：Bruce Chapman

**结论：长行 read 确实遮住了答案；成功 rerank 恢复了原文证据。**

- T4 对论文 read(limit=80)，L34 在前 2,000 字符后截断 11,747 字符，致谢没有显示。T8 改为 offset=32、limit=3，仍只能读到同一行开头，减少行数不能恢复后半行。两次返回的结构化 `result_truncated` 都是 false，但正文明确有 `[line truncated; ...]`，审计截断需同时检查正文标记。
- T5、T6、T9 把 `file_paths` 传成 JSON 数组的字符串，均得到明确的“必须为数组”拒错；这是调用类型错误，不能归作模型评分后端故障。C 条件删去了含 Bash 步骤的整段示例，也失去了合法数组示例，值得补充独立的有效 JSON 示例；小样本不足以确认它就是错误原因。
- T7 取消该参数、做全池 rerank，关键致谢从 BM25 第 7→rerank 第 1，完整显示 Bruce Chapman，且附 `read_may_truncate=true`。T11 第二次全池 rerank 用已知名字核对，同段再次居首。最终依据的是 rerank 的真实正文，不是被截断 read 中不存在的内容。
- no_bash 下不能通过 Bash 字符切片恢复长行；可考虑给 read 增加字符窗口，或提供只读的段落定位能力。模型则应在明确的类型拒错后修正数组，而非连续重复字符串参数。

## no_bash / q161：Kune Rima

**结论：歌名和曲序有直接来源，但存在一次顶满预算、后段重复确认及题目唯一性限制。**

- T0 在首次搜索前完成 21,336 tokens、API 247.62 秒；T1 完成 32,000 tokens、其中 reasoning 同为 32,000，API 581.62 秒，无工具动作，仅留下长度截断后重试标记。T2 重试完成 13,153 tokens、API 277.37 秒后继续搜索。这里确有单次预算顶满后的恢复，不应当作终态失败，也不应把这些延迟算给检索或 rerank。
- T3 rerank 将 Thomas Mapfumo 17 岁寻父段从 BM25 第 452 提到第 3；T4–5 read 确认 1945 年出生、17 岁寻父、父亲 1973 年去世。这是另一处清晰的重排价值。
- T10 Bandcamp L88–90 明确第 6 首为 Kune Rima；T11 L162 明确该版本发行于 2000-09-04。随后又做多个其他专辑查询，T14 重复 Toi Toi/Rise Up 查询，直到 T16 才最终回答。T13 第二次 rerank 没有新增第六首曲序证据。
- 关于“截至 2023 年”：T7 Zimbabwe Mail 文件头日期为 2025，但 T12 Pindula 正文明写弟弟在 2022 年 9 月去世，故最终并非只有 2025 年材料才支持这条线索。
- 源材料需保留限定：T5 传记还提到已故女儿 Charity；Pindula 列五个子女，可能对应在世子女，模型未解释口径。T15 博客写 Chimurenga Explosion 为 1999 年，而 Bandcamp 与另外两份唱片目录写 2000 年，可能是版本差异，不能无条件宣称资料完全一致。
- 最终主动说明是“来源中唯一有完整曲目的 2000 年代专辑”，这一限定可取；题目没有提供能在所有该年代专辑间唯一识别专辑的线索。找到一张符合条件的专辑、并读到第六首，支持当前答案，尚不能证明不存在其他候选。该例不是毫无证据碰巧命中，但确定性低于人物识别和曲序这两项直接证据。

## 跨样本可操作结论

1. 优先澄清 Bash 的临时目录生命周期，并保留 C 的合法数组示例；严格参数拒错本身正常。
2. 为长行提供可恢复的字符窗口；审计应识别正文内截断标记，避免只依赖结构化 flag。
3. 在重复搜索无新证据时切换正文定位；得到答案及关键约束证据后停止重复确认。明确区分检索准备、评分、API 思考耗时。
4. 本抽样支持 rerank 能把深位正文带入可见前列（B153 第 265→8、C161 第 452→3）；A153 原本第 1→1 则主要提供导航。两个 A 正确样本都没用翻页，不能用其正确结果宣称翻页机制有效。
5. 六例均看到实际支持最终答案的正文；C161 的专辑唯一性、来源年份与子女口径，以及 A/B153 的搬迁年份差异，应作为证据限定保留。
